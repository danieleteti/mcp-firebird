# MCP Firebird 0.5.0 (free edition) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the free edition two things it has never had — visibility into PSQL objects (procedures, triggers, functions, packages), and a backup it proves is restorable.

**Architecture:** PSQL introspection extends the existing `Firebird.Introspection` → `Firebird.DocGen` pair with no new units and no new host access. Backup adds one new `sources/` unit that drives a local `gbak.exe` through temp files, exactly as `Firebird.PlanAnalyzer` already drives a local `isql.exe` — the second and last sanctioned exception to the core boundary's no-process-spawning rule. A backup takes minutes and an MCP call must not, so a `providers/` job unit runs it on a worker thread and the tools split into `fb_backup_start` (returns at once) and `fb_backup_status` (poll) — the shape the Enterprise `fb_trace_*` stubs already announce. The backup destination is declared once in `.env`; the tools never accept a caller-supplied path.

**Tech Stack:** Delphi 13 Athens, FireDAC, DMVCFramework MCP attributes, DUnitX, pytest.

## Global Constraints

- Firebird 2.5, 3.0, 4.0 and 5.0 must all stay green. Anything 3.0+ is gated through `Firebird.Capabilities`, never assumed.
- `sources/*.pas` must never import `MVCFramework.*` — enforced by `invoke boundary`.
- New production sources carry the SPDX header `LicenseRef-PolyForm-Internal-Use-1.0.0` plus the copyright/showcase lines, copied verbatim from an existing `sources/` unit.
- Every advisory-producing function returns `TAdvisory`; every MCP tool body runs inside `Guard()`.
- Free edition = ordinary SQL connection plus, now, a **local** `gbak.exe`. Never `isc_service_*`, `isc_spb_*`, `isc_action_svc_*`, `TFDPhysFBService` or `service_mgr` — that ban has no allowlist and is absolute.
- Build with `invoke build` / test with `pwsh tests/run_all.ps1`. Never call `msbuild` or `pwsh` build scripts directly.
- Every new DUnitX fixture needs **two** edits to `tests/coreproject/MCPFirebirdCoreTests.dpr`: a `uses` entry *and* an explicit `TDUnitX.RegisterTestFixture(...)` call. One without the other silently does not run.
- Adding a free tool name requires updating `FREE_TOOLS` in `tests/test_mcp_firebird_full.py`, which is **shared with the Enterprise repo** — the Enterprise executable must be rebuilt before its copy of the suite passes again.

Add the trigger-type decoder as a free function above the class implementation. The encoding packs up to three actions into two-bit slots, `1=INSERT 2=UPDATE 3=DELETE`, with bit 0 selecting BEFORE/AFTER:

```pascal
{ RDB$TRIGGER_TYPE packs up to three actions into 2-bit slots above bit 0, which
  is 0 for BEFORE and 1 for AFTER. Values above 113 are database-level triggers
  (ON CONNECT and friends), which carry no action slots at all. }
function DecodeTriggerType(AType: Int64): string;
const
  ACTIONS: array[1..3] of string = ('INSERT', 'UPDATE', 'DELETE');
var
  lSlot, lAction: Integer;
  lParts: TArray<string>;
begin
  if AType > 113 then
    Exit('ON ' + IntToStr(AType) + ' (database-level)');
  lParts := [];
  for lSlot := 0 to 2 do
  begin
    lAction := ((AType + 1) shr (1 + 2 * lSlot)) and 3;
    if lAction in [1 .. 3] then
      lParts := lParts + [ACTIONS[lAction]];
  end;
  if Length(lParts) = 0 then
    Exit('UNKNOWN');
  if (AType and 1) = 0 then
    Result := 'BEFORE '
  else
    Result := 'AFTER ';
  Result := Result + string.Join(' OR ', lParts);
end;
```

Then the three methods. `RDB$PACKAGE_NAME` does not exist before 3.0, so the column is only selected when the engine has packages:

```pascal
function TFirebirdIntrospection.RoutineParams(const ARoutine, APackage: string): TArray<TRoutineParam>;
var
  Q: TFDQuery;
  L: TList<TRoutineParam>;
  R: TRoutineParam;
  lSQL: string;
begin
  lSQL :=
    'SELECT TRIM(p.RDB$PARAMETER_NAME) AS PNAME, p.RDB$PARAMETER_NUMBER AS PNUM, ' +
    '       p.RDB$PARAMETER_TYPE AS PTYPE, f.RDB$FIELD_TYPE AS FTYPE, ' +
    '       f.RDB$FIELD_LENGTH AS FLEN, f.RDB$FIELD_SCALE AS FSCALE ' +
    'FROM RDB$PROCEDURE_PARAMETERS p ' +
    'JOIN RDB$FIELDS f ON f.RDB$FIELD_NAME = p.RDB$FIELD_SOURCE ' +
    'WHERE p.RDB$PROCEDURE_NAME = ' + QuotedStr(ARoutine);
  if FCaps.HasPackages then
    if APackage = '' then
      lSQL := lSQL + ' AND p.RDB$PACKAGE_NAME IS NULL'
    else
      lSQL := lSQL + ' AND p.RDB$PACKAGE_NAME = ' + QuotedStr(APackage);
  lSQL := lSQL + ' ORDER BY p.RDB$PARAMETER_TYPE, p.RDB$PARAMETER_NUMBER';

  L := TList<TRoutineParam>.Create;
  try
    Q := FConn.OpenQuery(lSQL);
    try
      while not Q.Eof do
      begin
        R := Default(TRoutineParam);
        R.ParamName := Q.FieldByName('PNAME').AsString;
        R.Position := Q.FieldByName('PNUM').AsInteger;
        R.IsOutput := Q.FieldByName('PTYPE').AsInteger = 1;
        R.DataType := MapFieldType(Q.FieldByName('FTYPE').AsInteger,
          Q.FieldByName('FLEN').AsInteger, Q.FieldByName('FSCALE').AsInteger);
        L.Add(R);
        Q.Next;
      end;
    finally
      Q.Free;
    end;
    Result := L.ToArray;
  finally
    L.Free;
  end;
end;

function TFirebirdIntrospection.ListProcedures: TArray<TProcedureInfo>;
var
  Q: TFDQuery;
  L: TList<TProcedureInfo>;
  P: TProcedureInfo;
  lSQL: string;
begin
  if FCaps.HasPackages then
    lSQL := 'SELECT TRIM(RDB$PROCEDURE_NAME) AS PNAME, ' +
            '       COALESCE(TRIM(RDB$PACKAGE_NAME), '''') AS PKG ' +
            'FROM RDB$PROCEDURES ' +
            'WHERE COALESCE(RDB$SYSTEM_FLAG, 0) = 0 ORDER BY 2, 1'
  else
    lSQL := 'SELECT TRIM(RDB$PROCEDURE_NAME) AS PNAME, '''' AS PKG ' +
            'FROM RDB$PROCEDURES ' +
            'WHERE COALESCE(RDB$SYSTEM_FLAG, 0) = 0 ORDER BY 1';

  L := TList<TProcedureInfo>.Create;
  try
    Q := FConn.OpenQuery(lSQL);
    try
      while not Q.Eof do
      begin
        P := Default(TProcedureInfo);
        P.ProcName := Q.FieldByName('PNAME').AsString;
        P.PackageName := Q.FieldByName('PKG').AsString;
        L.Add(P);
        Q.Next;
      end;
    finally
      Q.Free;
    end;
    Result := L.ToArray;
  finally
    L.Free;
  end;
  { Parameters are fetched after the cursor is closed: one open query at a time
    keeps this working on every engine in the matrix. }
  for var lIdx := 0 to High(Result) do
    Result[lIdx].Params := RoutineParams(Result[lIdx].ProcName, Result[lIdx].PackageName);
end;

function TFirebirdIntrospection.ListTriggers(const ATable: string = ''): TArray<TTriggerInfo>;
var
  Q: TFDQuery;
  L: TList<TTriggerInfo>;
  T: TTriggerInfo;
  lSQL: string;
begin
  lSQL :=
    'SELECT TRIM(RDB$TRIGGER_NAME) AS TNAME, COALESCE(TRIM(RDB$RELATION_NAME), '''') AS TBL, ' +
    '       RDB$TRIGGER_TYPE AS TTYPE, COALESCE(RDB$TRIGGER_SEQUENCE, 0) AS TSEQ, ' +
    '       COALESCE(RDB$TRIGGER_INACTIVE, 0) AS TINACT ' +
    'FROM RDB$TRIGGERS WHERE COALESCE(RDB$SYSTEM_FLAG, 0) = 0';
  if ATable <> '' then
    lSQL := lSQL + ' AND RDB$RELATION_NAME = ' + QuotedStr(ATable);
  lSQL := lSQL + ' ORDER BY 2, 4, 1';

  L := TList<TTriggerInfo>.Create;
  try
    Q := FConn.OpenQuery(lSQL);
    try
      while not Q.Eof do
      begin
        T := Default(TTriggerInfo);
        T.TriggerName := Q.FieldByName('TNAME').AsString;
        T.TableName := Q.FieldByName('TBL').AsString;
        T.Event := DecodeTriggerType(Q.FieldByName('TTYPE').AsLargeInt);
        T.Position := Q.FieldByName('TSEQ').AsInteger;
        T.Inactive := Q.FieldByName('TINACT').AsInteger <> 0;
        L.Add(T);
        Q.Next;
      end;
    finally
      Q.Free;
    end;
    Result := L.ToArray;
  finally
    L.Free;
  end;
end;
```

```pascal
function TFirebirdIntrospection.ListFunctions: TArray<TFunctionInfo>;
var
  Q: TFDQuery;
  L: TList<TFunctionInfo>;
  F: TFunctionInfo;
begin
  Result := [];
  if not FCaps.HasPackages then
    Exit;
  L := TList<TFunctionInfo>.Create;
  try
    Q := FConn.OpenQuery(
      'SELECT TRIM(f.RDB$FUNCTION_NAME) AS FNAME, ' +
      '       COALESCE(TRIM(f.RDB$PACKAGE_NAME), '''') AS PKG, ' +
      '       fl.RDB$FIELD_TYPE AS FTYPE, fl.RDB$FIELD_LENGTH AS FLEN, ' +
      '       fl.RDB$FIELD_SCALE AS FSCALE ' +
      'FROM RDB$FUNCTIONS f ' +
      'LEFT JOIN RDB$FUNCTION_ARGUMENTS a ' +
      '  ON a.RDB$FUNCTION_NAME = f.RDB$FUNCTION_NAME ' +
      ' AND a.RDB$ARGUMENT_POSITION = f.RDB$RETURN_ARGUMENT ' +
      ' AND COALESCE(a.RDB$PACKAGE_NAME, '''') = COALESCE(f.RDB$PACKAGE_NAME, '''') ' +
      'LEFT JOIN RDB$FIELDS fl ON fl.RDB$FIELD_NAME = a.RDB$FIELD_SOURCE ' +
      'WHERE COALESCE(f.RDB$SYSTEM_FLAG, 0) = 0 ORDER BY 2, 1');
    try
      while not Q.Eof do
      begin
        F := Default(TFunctionInfo);
        F.FuncName := Q.FieldByName('FNAME').AsString;
        F.PackageName := Q.FieldByName('PKG').AsString;
        if Q.FieldByName('FTYPE').IsNull then
          F.ReturnType := 'UNKNOWN'
        else
          F.ReturnType := MapFieldType(Q.FieldByName('FTYPE').AsInteger,
            Q.FieldByName('FLEN').AsInteger, Q.FieldByName('FSCALE').AsInteger);
        L.Add(F);
        Q.Next;
      end;
    finally
      Q.Free;
    end;
    Result := L.ToArray;
  finally
    L.Free;
  end;
end;

function TFirebirdIntrospection.ListPackages: TArray<TPackageInfo>;
var
  Q: TFDQuery;
  L: TList<TPackageInfo>;
  P: TPackageInfo;
begin
  Result := [];
  if not FCaps.HasPackages then
    Exit;
  L := TList<TPackageInfo>.Create;
  try
    Q := FConn.OpenQuery(
      'SELECT TRIM(RDB$PACKAGE_NAME) AS PKG, ' +
      '       IIF(RDB$PACKAGE_BODY_SOURCE IS NULL, 0, 1) AS HAS_BODY ' +
      'FROM RDB$PACKAGES WHERE COALESCE(RDB$SYSTEM_FLAG, 0) = 0 ORDER BY 1');
```

**Files:**
- Create: `sources/Firebird.Backup.pas`
- Modify: `tests/check_core_boundary.ps1`
- Modify: `tests/coreproject/MCPFirebirdCoreTests.dpr`
- Create: `tests/coreproject/Test.Firebird.Backup.pas`

**Interfaces:**
- Consumes: `TFirebirdConnectionConfig` (Host, Port, Database, User, Password, ClientLib) **by value**.
- Produces: `TBackupOutcome` and `TVerifyOutcome` records; `TFirebirdBackup.Create(const AConfig: TFirebirdConnectionConfig)`, the class function `ProposeBackupFile(const ADatabase, ADestDir: string): string`, `.Backup(const ABackupFile: string): TBackupOutcome`, `.VerifyRestore(const ABackupFile, AScratchDir: string): TVerifyOutcome`. Task 6 drives all three from a worker thread.

**Why the filename is proposed separately and passed in:** the job publishes the destination
*before* the backup starts, so `fb_backup_status` can report the growing file during the long
phase. A `Backup` that invented its own name could only reveal it on the way out — progress that
stands still while the work happens defeats the polling this whole design exists for.

**Why a config record and not a connection:** the backup runs on a background thread that
outlives the tool call, and `Guard` frees its connection the moment the body returns. This unit
never issues SQL — it spawns `gbak` — so it needs the connection *parameters*, not the
connection. Taking a value record makes that explicit and leaves nothing shared between threads.

**Why two methods and not one `Run`:** the caller reports which phase it is in while it waits.
Splitting the long operation at its one natural seam lets the job own that state without a
callback, and lets each half be tested on its own.

Create `sources/Firebird.Backup.pas`. The `gbak` location and the `CreateProcess`/timeout shape are copied from `Firebird.PlanAnalyzer` deliberately — same rationale, same failure modes, so they should read the same:

```pascal
// SPDX-License-Identifier: LicenseRef-PolyForm-Internal-Use-1.0.0
// Copyright 2026 Daniele Teti — https://github.com/danieleteti/mcp-firebird
// Part of MCP Firebird, a showcase for https://github.com/danieleteti/mcp-server-delphi
unit Firebird.Backup;

{ Drives a LOCAL gbak.exe, the way Firebird.PlanAnalyzer drives a local isql.exe:
  a client tool on this machine, through temp files, never the server's own files
  and never the Services Manager. That is what keeps it inside the free edition.

  A backup nobody has restored is a file, not a backup. Run() therefore restores
  what it just wrote into a scratch database and throws it away — with gbak -c,
  which CREATES and refuses an existing file, so a bug here cannot land on the
  live database however wrong the path turns out to be. }

interface

uses Firebird.Connection;

type
  TBackupOutcome = record
    BackupFile: string;
    BackupBytes: Int64;
    BackupSeconds: Double;
    GbakLog: string;        // tail of gbak's own output, for the report
  end;

  TVerifyOutcome = record
    Restored: Boolean;
    Seconds: Double;
    Detail: string;         // how it failed, when it did
  end;

  TFirebirdBackup = class
  private
    FConfig: TFirebirdConnectionConfig;
    function GbakPath: string;
    function ConnectString: string;
    procedure RunAndWait(const ACmd: string; ATimeoutMs: Cardinal; const AWhat: string);
  public
    { Takes the connection parameters by value, not a connection: this runs on a
      worker thread that outlives the tool call, and it issues no SQL. }
    constructor Create(const AConfig: TFirebirdConnectionConfig);
    { The name the next backup would get. Public so the caller can publish the
      destination before the backup starts, and report the file growing. }
    class function ProposeBackupFile(const ADatabase, ADestDir: string): string; static;
    { ABackupFile's folder must exist and the file must not. Raises on any failure. }
    function Backup(const ABackupFile: string): TBackupOutcome;
    { Restores ABackupFile into a scratch database under AScratchDir and deletes it
      again. Never raises: a restore that cannot run is the answer, not an accident. }
    function VerifyRestore(const ABackupFile, AScratchDir: string): TVerifyOutcome;
  end;

implementation

uses
  Winapi.Windows, System.SysUtils, System.IOUtils, System.Diagnostics, System.Classes;

const
  BACKUP_TIMEOUT_MS = 30 * 60 * 1000;   // half an hour; a real database is not an isql plan
  LOG_TAIL_CHARS = 2000;

constructor TFirebirdBackup.Create(const AConfig: TFirebirdConnectionConfig);
begin
  inherited Create;
  FConfig := AConfig;
end;

function TFirebirdBackup.GbakPath: string;
var
  lDir: string;
begin
  lDir := ExtractFilePath(FConfig.ClientLib);
  if lDir <> '' then
    Result := IncludeTrailingPathDelimiter(lDir) + 'gbak.exe'
  else
    Result := 'gbak.exe';
  if not FileExists(Result) then
    Result := 'gbak.exe';
end;

function TFirebirdBackup.ConnectString: string;
begin
  Result := Format('%s/%d:%s', [FConfig.Host, FConfig.Port, FConfig.Database]);
end;

procedure TFirebirdBackup.RunAndWait(const ACmd: string; ATimeoutMs: Cardinal; const AWhat: string);
var
  SI: TStartupInfo;
  PI: TProcessInformation;
  lCmd: string;
  lExit: Cardinal;
begin
  FillChar(SI, SizeOf(SI), 0);
  SI.cb := SizeOf(SI);
  SI.dwFlags := STARTF_USESHOWWINDOW;
  SI.wShowWindow := SW_HIDE;
  lCmd := ACmd;
  UniqueString(lCmd);
  if not CreateProcess(nil, PChar(lCmd), nil, nil, False, CREATE_NO_WINDOW, nil, nil, SI, PI) then
    RaiseLastOSError;
  try
    if WaitForSingleObject(PI.hProcess, ATimeoutMs) = WAIT_TIMEOUT then
    begin
      TerminateProcess(PI.hProcess, 1);
      raise Exception.CreateFmt('%s timed out after %d minutes', [AWhat, ATimeoutMs div 60000]);
    end;
    if not GetExitCodeProcess(PI.hProcess, lExit) then
      RaiseLastOSError;
    if lExit <> 0 then
      raise Exception.CreateFmt('%s failed (gbak exit code %d)', [AWhat, lExit]);
  finally
    CloseHandle(PI.hThread);
    CloseHandle(PI.hProcess);
  end;
end;

class function TFirebirdBackup.ProposeBackupFile(const ADatabase, ADestDir: string): string;
begin
  Result := IncludeTrailingPathDelimiter(ADestDir) +
    Format('%s-%s.fbk', [ChangeFileExt(ExtractFileName(ADatabase), ''),
                         FormatDateTime('yyyymmdd-hhnnss', Now)]);
end;

function TFirebirdBackup.Backup(const ABackupFile: string): TBackupOutcome;
var
  lLogFile: string;
  SW: TStopwatch;
begin
  Result := Default(TBackupOutcome);
  if not TDirectory.Exists(ExtractFileDir(ABackupFile)) then
    raise Exception.CreateFmt('Backup destination does not exist: %s',
      [ExtractFileDir(ABackupFile)]);
  if TFile.Exists(ABackupFile) then
    raise Exception.CreateFmt('Refusing to overwrite an existing backup: %s', [ABackupFile]);
  Result.BackupFile := ABackupFile;

  lLogFile := TPath.GetTempFileName;
  try
    SW := TStopwatch.StartNew;
    RunAndWait(Format('"%s" -b -v -y "%s" -user %s -password %s "%s" "%s"',
      [GbakPath, lLogFile, FConfig.User, FConfig.Password,
       ConnectString, Result.BackupFile]), BACKUP_TIMEOUT_MS, 'Backup');
    Result.BackupSeconds := SW.Elapsed.TotalSeconds;

    if not TFile.Exists(Result.BackupFile) then
      raise Exception.CreateFmt('gbak reported success but wrote no file: %s', [Result.BackupFile]);
    Result.BackupBytes := TFile.GetSize(Result.BackupFile);
    Result.GbakLog := TFile.ReadAllText(lLogFile);
    if Result.GbakLog.Length > LOG_TAIL_CHARS then
      Result.GbakLog := '...' + Result.GbakLog.Substring(Result.GbakLog.Length - LOG_TAIL_CHARS);
  finally
    if TFile.Exists(lLogFile) then
      TFile.Delete(lLogFile);
  end;
end;

function TFirebirdBackup.VerifyRestore(const ABackupFile, AScratchDir: string): TVerifyOutcome;
var
  lLogFile, lScratch: string;
  SW: TStopwatch;
begin
  Result := Default(TVerifyOutcome);
  { -c CREATES and refuses an existing file. Combined with a name nothing else uses,
    a bug here cannot land on the live database however wrong the path turns out. }
  lScratch := IncludeTrailingPathDelimiter(AScratchDir) +
    Format('verify-%s.scratch.fdb', [FormatDateTime('yyyymmdd-hhnnsszzz', Now)]);
  lLogFile := TPath.GetTempFileName;
```

### Task 6: Run the backup on a worker thread

**Files:**
- Create: `providers/FirebirdBackupJobU.pas`
- Modify: `app/MCPFirebird.dpr`
- Test: none here — the job is covered end-to-end by the Python test in Task 7 (see Step 2)

**Interfaces:**
- Consumes: `TFirebirdBackup.Backup` / `.VerifyRestore` (Task 5), `TFirebirdConnectionConfig`.
- Produces: `TBackupPhase = (bpNever, bpBackingUp, bpVerifying, bpDone, bpFailed)`; `TBackupJobState` record; `StartBackupJob(const AConfig: TFirebirdConnectionConfig; const ADestDir: string): Boolean`; `BackupJobState: TBackupJobState`. Task 7 calls both.

**Why this lives in `providers/` and not `sources/`:** the asynchrony exists because MCP is
request/response and cannot stream progress. It is a protocol-shaped concern, not a Firebird
one, and `sources/` stays synchronous and directly testable because of it.

**One job at a time, no job ids.** A second concurrent backup of the same database is not a
feature anyone asked for; it is contention for disk and a way to write two files at once. The
job is a single slot: `StartBackupJob` returns False when one is already running.

- [ ] **Step 1: Write the unit**

Create `providers/FirebirdBackupJobU.pas`:

```pascal
// SPDX-License-Identifier: LicenseRef-PolyForm-Internal-Use-1.0.0
// Copyright 2026 Daniele Teti — https://github.com/danieleteti/mcp-firebird
// Part of MCP Firebird, a showcase for https://github.com/danieleteti/mcp-server-delphi
unit FirebirdBackupJobU;

{ A backup takes minutes; an MCP call must not. So fb_backup_start hands the work
  to a thread and returns at once, and fb_backup_status reports on it — the same
  start/poll shape the Enterprise fb_trace_* tools use, for the same reason.

  One slot, no job ids: two concurrent backups of one database is disk contention
  wearing the costume of a feature. }

interface

uses System.SysUtils, Firebird.Connection;

type
  TBackupPhase = (bpNever, bpBackingUp, bpVerifying, bpDone, bpFailed);

  TBackupJobState = record
    Phase: TBackupPhase;
    StartedAt: TDateTime;
    FinishedAt: TDateTime;
    BackupFile: string;
    BackupBytes: Int64;      // final size; while running, ask the file itself
    BackupSeconds: Double;
    VerifySeconds: Double;
    Detail: string;          // the failure, or the verification's complaint
    GbakLog: string;
    function Running: Boolean;
  end;

{ False when a backup is already running — the caller should poll instead of starting another. }
function StartBackupJob(const AConfig: TFirebirdConnectionConfig; const ADestDir: string): Boolean;
function BackupJobState: TBackupJobState;

implementation

uses
  System.Classes, System.IOUtils, System.SyncObjs, Firebird.Backup, MVCFramework.Logger;

var
  GLock: TCriticalSection;
  GState: TBackupJobState;

function TBackupJobState.Running: Boolean;
begin
  Result := Phase in [bpBackingUp, bpVerifying];
end;

procedure SetPhase(APhase: TBackupPhase);
begin
  GLock.Enter;
  try
    GState.Phase := APhase;
  finally
    GLock.Leave;
  end;
end;

function StartBackupJob(const AConfig: TFirebirdConnectionConfig; const ADestDir: string): Boolean;
var
  lConfig: TFirebirdConnectionConfig;
  lDir: string;
begin
  GLock.Enter;
  try
    if GState.Running then
      Exit(False);
    GState := Default(TBackupJobState);
    GState.Phase := bpBackingUp;
    GState.StartedAt := Now;
    Result := True;
  finally
    GLock.Leave;
  end;

  { Captured by value: the thread must share nothing with the request that started it. }
  lConfig := AConfig;
  lDir := ADestDir;

  TThread.CreateAnonymousThread(
    procedure
    var
      B: TFirebirdBackup;
      O: TBackupOutcome;
      V: TVerifyOutcome;
      lFile: string;
    begin
      B := TFirebirdBackup.Create(lConfig);
      try
        try
          { Publish the destination BEFORE the long phase starts, so
            BackupJobState can report the file growing while it runs. }
          lFile := TFirebirdBackup.ProposeBackupFile(lConfig.Database, lDir);
          GLock.Enter;
          try
            GState.BackupFile := lFile;
          finally
            GLock.Leave;
          end;

          O := B.Backup(lFile);
          GLock.Enter;
          try
            GState.BackupBytes := O.BackupBytes;
            GState.BackupSeconds := O.BackupSeconds;
            GState.GbakLog := O.GbakLog;
            GState.Phase := bpVerifying;
          finally
            GLock.Leave;
          end;
          LogI(Format('backup written %s (%d bytes)', [O.BackupFile, O.BackupBytes]), 'mcp');

          V := B.VerifyRestore(O.BackupFile, lDir);
          GLock.Enter;
          try
            GState.VerifySeconds := V.Seconds;
            GState.Detail := V.Detail;
            if V.Restored then
              GState.Phase := bpDone
            else
              GState.Phase := bpFailed;
            GState.FinishedAt := Now;
          finally
            GLock.Leave;
          end;
        except
          on E: Exception do
          begin
            GLock.Enter;
            try
              GState.Phase := bpFailed;
              GState.Detail := E.ClassName + ': ' + E.Message;
              GState.FinishedAt := Now;
            finally
              GLock.Leave;
            end;
            LogException(E, 'backup job failed');
          end;
        end;
      finally
        B.Free;
      end;
    end).Start;
end;

function BackupJobState: TBackupJobState;
begin
  GLock.Enter;
  try
    Result := GState;
  finally
    GLock.Leave;
  end;
  { While the backup is running the file on disk is the honest progress counter,
    and reading its size costs nothing. No shared counter to keep in step. }
  if (Result.Phase = bpBackingUp) and (Result.BackupFile <> '') and TFile.Exists(Result.BackupFile) then
    Result.BackupBytes := TFile.GetSize(Result.BackupFile);
end;

initialization
  GLock := TCriticalSection.Create;
  GState := Default(TBackupJobState);

finalization
  GLock.Free;

end.
```

The `bpBackingUp` branch of `BackupJobState` and the publish-before-backup above are one
mechanism: neither is worth anything without the other. If either is changed, check the other.

```pascal
var
  S: TBackupJobState;
  SB: TStringBuilder;
begin

    on a thread would be the only thing that could make it fail. }
  LogI('>> fb_backup_status', 'mcp');
  S := BackupJobState;
  SB := TStringBuilder.Create;
  try
    case S.Phase of
      bpNever:
        SB.AppendLine('No backup has been started since this server started. Use fb_backup_start.');
      bpBackingUp:

          '**Verifying** — still running. The backup finished in %.1fs (%.1f MB) and is now ' +
          'being restored into a scratch database.', [S.BackupSeconds, S.BackupBytes / 1024 / 1024]));
      bpDone:

          SB.AppendLine(Format('**Size:** %.1f MB  **Backup:** %.1fs  **Verify:** %.1fs',

          SB.AppendLine;
          SB.AppendLine('The backup was restored into a scratch database and then deleted. ' +
            'It is a backup, not just a file.');

        end;

    if S.GbakLog <> '' then
      SB.AppendLine.AppendLine('```').AppendLine(S.GbakLog.Trim).AppendLine('```');
```

```pascal
unit Firebird.Attachments;

{ Who is attached, from where, and what each one is running right now.

  This is a snapshot of state, not of waiting: MON$ counts work performed and has
  no column for time spent waiting for permission to perform it. An attachment
  blocked on another one's lock looks exactly like an attachment that is busy. }

interface

uses Firebird.Connection, Firebird.Capabilities, Firebird.Advisory;

type
  TAttachmentInfo = record
    AttachmentID: Int64;
    UserName: string;
    RemoteAddress: string;
    RemoteProcess: string;
    Active: Boolean;
    ConnectedSeconds: Int64;
    CurrentSQL: string;       // '' when the attachment is running nothing
    StatementSeconds: Int64;  // age of that statement, 0 when there is none
  end;

  TFirebirdAttachments = class
  private
    FConn: TFirebirdConnection;
    FCaps: TFirebirdCapabilities;
  public
    constructor Create(AConn: TFirebirdConnection; const ACaps: TFirebirdCapabilities);
    function List: TArray<TAttachmentInfo>;
    function Analyze(AIdleMinutes, ALongStatementSeconds: Integer): TArray<TAdvisory>;
  end;

implementation

uses System.SysUtils, System.Generics.Collections, FireDAC.Comp.Client;

const
  SQL_TEXT_LIMIT = 300;

constructor TFirebirdAttachments.Create(AConn: TFirebirdConnection;
  const ACaps: TFirebirdCapabilities);
begin
  inherited Create;
  FConn := AConn;
  FCaps := ACaps;
end;

function TFirebirdAttachments.List: TArray<TAttachmentInfo>;
var
  Q: TFDQuery;
  L: TList<TAttachmentInfo>;
  T: TAttachmentInfo;
begin
  Result := [];
  if not FCaps.HasMonTables then
    Exit;
  L := TList<TAttachmentInfo>.Create;
  try
    { The newest statement per attachment: MON$STATEMENTS keeps finished ones too,
      so ordering by timestamp and taking the first is what "running now" means here. }
    Q := FConn.OpenQuery(
      'SELECT a.MON$ATTACHMENT_ID AS AID, TRIM(a.MON$USER) AS AUSER, ' +
      '       COALESCE(TRIM(a.MON$REMOTE_ADDRESS), '''') AS ADDR, ' +
      '       COALESCE(TRIM(a.MON$REMOTE_PROCESS), '''') AS PROC, ' +
      '       COALESCE(a.MON$STATE, 0) AS ASTATE, ' +
      '       DATEDIFF(SECOND, a.MON$TIMESTAMP, CURRENT_TIMESTAMP) AS AGE_S, ' +
      '       (SELECT FIRST 1 TRIM(s.MON$SQL_TEXT) FROM MON$STATEMENTS s ' +
      '         WHERE s.MON$ATTACHMENT_ID = a.MON$ATTACHMENT_ID AND s.MON$STATE = 1 ' +
      '         ORDER BY s.MON$TIMESTAMP DESC) AS CUR_SQL, ' +
      '       (SELECT FIRST 1 DATEDIFF(SECOND, s.MON$TIMESTAMP, CURRENT_TIMESTAMP) ' +
      '          FROM MON$STATEMENTS s ' +
      '         WHERE s.MON$ATTACHMENT_ID = a.MON$ATTACHMENT_ID AND s.MON$STATE = 1 ' +
      '         ORDER BY s.MON$TIMESTAMP DESC) AS SQL_AGE_S ' +
      'FROM MON$ATTACHMENTS a ORDER BY a.MON$ATTACHMENT_ID');
    try
      while not Q.Eof do
      begin
        T := Default(TAttachmentInfo);
        T.AttachmentID := Q.FieldByName('AID').AsLargeInt;
        T.UserName := Q.FieldByName('AUSER').AsString;
        T.RemoteAddress := Q.FieldByName('ADDR').AsString;
        T.RemoteProcess := Q.FieldByName('PROC').AsString;
        T.Active := Q.FieldByName('ASTATE').AsInteger = 1;
        T.ConnectedSeconds := Q.FieldByName('AGE_S').AsLargeInt;
        T.CurrentSQL := Q.FieldByName('CUR_SQL').AsString;
        if T.CurrentSQL.Length > SQL_TEXT_LIMIT then
          T.CurrentSQL := T.CurrentSQL.Substring(0, SQL_TEXT_LIMIT) + '...';
        if not Q.FieldByName('SQL_AGE_S').IsNull then
          T.StatementSeconds := Q.FieldByName('SQL_AGE_S').AsLargeInt;
        L.Add(T);
        Q.Next;
      end;
    finally
      Q.Free;
    end;
    Result := L.ToArray;
  finally
    L.Free;
  end;
end;

function TFirebirdAttachments.Analyze(AIdleMinutes, ALongStatementSeconds: Integer): TArray<TAdvisory>;
var
  L: TList<TAdvisory>;
  T: TAttachmentInfo;
  lAll: TArray<TAttachmentInfo>;
  lIdle: Integer;
begin
  if not FCaps.HasMonTables then
    Exit([TAdvisory.Make(
      'Monitoring tables (MON$*) are not available on this engine version.',
      '', '', 'info')]);

  lAll := List;
  L := TList<TAdvisory>.Create;
  try
    lIdle := 0;
    for T in lAll do
    begin
      if (not T.Active) and (T.ConnectedSeconds > AIdleMinutes * 60) then
        Inc(lIdle);
      if T.StatementSeconds > ALongStatementSeconds then
        L.Add(TAdvisory.Make(
          Format('Attachment %d (%s from %s) has been running one statement for %d seconds: %s',
            [T.AttachmentID, T.UserName,
             IfEmpty(T.RemoteAddress, 'local'), T.StatementSeconds, T.CurrentSQL]),
          '',
          'Re-run fb_monitor_attachments: a statement that is finished will no longer appear.',
          'warning'));
    end;

    if lIdle > 1 then
      L.Add(TAdvisory.Make(
        Format('%d attachments have been connected and idle for more than %d minutes. ' +
          'Idle attachments each hold a connection slot and memory; a pool that never ' +
          'shrinks and an application that never disconnects look the same from here.',
          [lIdle, AIdleMinutes]),
        '',
        'Re-run fb_monitor_attachments after the application has been quiet: a healthy ' +
        'pool keeps the count steady, a leak grows it.',
        'info'));

    Result := L.ToArray;
  finally
    L.Free;
  end;
end;

end.
```

## Not in this release, and why

**An FK-without-index detector was planned and dropped.** Firebird creates the index on the
child column itself when a `FOREIGN KEY` constraint is declared — verified against the seeded
database, where `FK_ORDERS_CUSTOMER` is an index on `ORDERS.CUSTOMER_ID` carrying
`RDB$FOREIGN_KEY = RDB$PRIMARY1`. The condition the detector would look for cannot arise from a
declared constraint; the idea came from engines that do not auto-index. What *does* exist on
Firebird is the mirror problem — an auto-created FK index with poor selectivity, paid for on
every write and undroppable while the constraint stands. That is a different detector and it is
not in 0.5.0.

## After the plan: the Enterprise repo

`tests/test_mcp_firebird_full.py` is shared. The moment `FREE_TOOLS` gains `fb_backup_start`,
`fb_backup_status` and `fb_monitor_attachments`, the Enterprise repo's suite fails until
`MCPFirebirdEnt.exe` is rebuilt from a source tree that includes all three. Sequence it
deliberately: land 0.5.0 here, then sync and rebuild Enterprise before running its suite.
Nothing in this plan touches `ENTERPRISE_STUBS`, so the locked-tool contract is unchanged.

The start/poll shape `fb_backup_start` + `fb_backup_status` adopts is the one
`fb_trace_start` / `fb_trace_status` / `fb_trace_stop` already announce from
`FirebirdStubsU`. When Enterprise implements those for real, `FirebirdBackupJobU`'s single-slot
job — critical section around a state record, thread captures its inputs by value, status
reads the artefact on disk rather than a shared counter — is the pattern to lift rather than
re-invent. If a second long job ever lands here too, that is the moment to generalise it into
one job registry; two is a coincidence, three is a type.
